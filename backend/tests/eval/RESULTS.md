# Note similarity benchmark

Generated by `tests/eval/benchmark.py`; do not edit by hand.

Command: `cd backend && venv/bin/python -m tests.eval.benchmark`

Run on 2026-10-14: Apple M3 Pro, 11 cores, Darwin arm64, Python 3.11.13.
Packages: fastembed 0.9.0, onnxruntime 1.31.0, scikit-learn 1.3.2.

## Corpus

105 synthetic lecture notes in `tests/eval/corpus/`, across 8 subjects (biology, chemistry, computer-science, economics, history, machine-learning, physics, psychology) and 32 topics of 3 to 4 notes each.
No real user notes are used.
Each note is one query; every other note is ranked by similarity, and a neighbour is relevant when it shares the query's topic.
Precision@k and recall@k are averaged over all queries, and tied scores are broken in a fixed random order.
The ceiling row is a perfect ranking: with 2 to 3 relevant notes per query, precision@5 cannot reach 100.

## Graph edges

`/graph` draws an edge for every pair of a user's notes above a similarity threshold, so this scores that edge set directly: precision and recall of same-topic pairs among the pairs above the threshold.
The corpus has 123 same-topic pairs out of 5460.
TF-IDF scores are the production boosted values, `min(1, 1.1 * sqrt(cosine))`, and production draws edges above 0.6.
Embedding scores are raw cosine similarity, and production draws edges above `EMBEDDING_SIMILARITY_THRESHOLD`, currently 0.7.
The best-F1 rows search thresholds from 0.2 to 0.95 on this same corpus, so they are an optimistic ceiling for each backend rather than a held-out result.

## Cost on this machine

| Backend | Model load | Per note, batch of the corpus | Per note, one at a time (median) |
|---|---:|---:|---:|
| TF-IDF | none | 0.14 ms (whole matrix 15 ms) | not applicable |
| bge-small-en-v1.5 | 0.26 s | 17.69 ms | 11.59 ms |
| all-MiniLM-L6-v2 | 0.08 s | 10.01 ms | 5.47 ms |

TF-IDF is refit on all of a user's notes on every `/graph` request.
Embeddings are computed once per note on create or update, and `/graph` only compares stored vectors in Postgres.
Model load is measured from the local cache and happens once per process; the first model listed also pays for importing fastembed.
